# HAOS-IIP Framework Comparison Matrix v1

Status:

- Phase 66 artifact
- comparison / rediscovery-control layer
- no new result
- no stronger physical claim

Purpose:

Compare HAOS-IIP with nearby established frameworks in standard language,
identifying overlap, difference, forbidden assumptions, possible rediscovery,
and candidate contribution.

Core rule:

```text
HAOS-IIP must state what it shares with existing frameworks before claiming
what it adds.
```

Important line:

```text
Rediscovery is not failure. Unmarked rediscovery is failure.
```

## How to Use This Matrix

Use this matrix before public summaries, papers, dashboards, and bridge claims.

For each claim:

1. Identify the nearest established framework.
2. State the overlap first.
3. State what HAOS-IIP forbids.
4. Mark the rediscovery risk.
5. State the test required before claiming an addition.

## Rediscovery Policy

Rediscovery is allowed.

Unmarked rediscovery is not.

If a HAOS-IIP result is mostly a known graph-Laplacian, DEC, Hodge, resilience,
or early-warning result, the correct outcome is to say so. That does not make
the work useless. It places the work in the right intellectual neighborhood and
shows where the remaining contribution must be tested.

## Authority Boundary

This matrix does not prove that HAOS-IIP adds something new.

It defines what must be checked before such a claim becomes mature.
