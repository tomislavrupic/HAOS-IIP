## 2. Current scale-bridge problem

HAOS-IIP has strong internal frozen-regime diagnostics, scalar-carrier geometry closure on one tested kernel-graph family, bounded proto-continuum evidence, and a reproducible late-phase propagation -> ordering -> causal-closure -> distance-surrogate chain.

That is meaningful.

It is not yet a proven continuum limit.

The current weakness is the scale bridge: the program can show refinement-ordered behavior and metric-like surrogate stabilization inside tested operator regimes, but it has not yet shown that these structures converge uniquely, universally, or physically toward a continuum geometry or continuum field theory.

The scale-bridge audit therefore asks:

```text
Is HAOS-IIP detecting structured refinement behavior,
or generic graph behavior with disciplined language?
```

The honest current status is:

- internal diagnostics are strong inside declared frozen regimes
- CP4 has a bounded shared-family scalar kernel-graph geometry closure
- proto-geometric surrogate behavior exists at the tested level
- CP5 universality is still open
- continuum ontology is not established

## 4. Refinement Scaling Ledger requirements

Every continuum-facing scale claim should create or reference a public refinement scaling ledger.

| Field | Meaning |
| --- | --- |

The ledger must make negative and control-matched rows visible. A clean-looking trend without its failed controls is not scale-bridge evidence.

## 5. Matched-control scaling comparison

Every scale-bridge claim must compare the branch result against controls chosen to be close enough to be dangerous.

Required control families, where applicable:

- random graph control
- shuffled-weight control
- matched-degree control
- non-admissible operator control
- perturbed-kernel control
- seed-randomized ensemble

The core question is:

```text
Is HAOS-IIP detecting structured refinement behavior,
or generic graph behavior?
```

Control comparison should happen at the same level as the claim. If the claim concerns eigenvalue scaling, compare eigenvalue scaling. If the claim concerns metric-like behavior, compare metric-like behavior. If the claim concerns coarse-law closure, compare equation-fit residuals and coefficient drift. Raw-observable separation is not enough when the public claim is about scale behavior.

## 7. Limited metric-like tests

For each metric surrogate or distance proxy, the document must test or explicitly defer:

- non-negativity
- identity behavior within numerical tolerance
- symmetry, when applicable
- triangle-inequality behavior or bounded violation
- refinement stability
- perturbation stability
- matched-control separation

Boundary:

Passing these tests means metric-like surrogate behavior stabilizes inside the tested operator regime.

It does not mean HAOS-IIP has derived spacetime or a physical metric.

Minimum status language:

| Result | Allowed statement |
| --- | --- |
| tests pass on one family | metric-like surrogate behavior stabilizes on the tested family |
| tests pass across several families | metric-like surrogate behavior shows bounded family robustness |
| controls fail but branch passes | branch/control separation supports a surrogate-level claim |
| triangle violations remain bounded but nonzero | metric-like behavior is approximate and tolerance-bound |
| controls reproduce the effect | no metric-surrogate claim; reduce to generic graph behavior |

## 8. Coarse-graining recovery test

Refinement alone is not enough. The structure must also survive compression.

For a refinement sequence

```text
h_0 > h_1 > h_2 > ...
```

with projection or coarse-grain maps

```text
Pi_{h_i -> h_j},   h_i < h_j,
```

the audit requires testing whether refined structure projects back to coarser levels while preserving:

- branch identity
- recoverability ranking
- spectral address persistence
- metric-surrogate ordering
- trace-ratio stability

Core question:

```text
Does the structure survive both refinement and compression?
```

Failure under compression means the apparent refinement trend may be a high-resolution artifact. A scale bridge should be able to move up and down the hierarchy without losing the claimed structure.

## 11. Failure gates

A scale-bridge claim fails if:

- measured structure does not stabilize under refinement
- stabilization is no better than matched controls
- metric-like behavior depends on hand-picked parameters
- branch identity changes unpredictably across refinement
- coarse-graining destroys the claimed structure
- error trends do not improve with refinement
- null models reproduce the same effect
- interpretation requires importing geometry by hand

When a failure gate triggers, the claim must shrink to the last surviving lower gate. A failed CP5 universality claim may still leave a valid CP4 one-family geometry closure. A failed metric surrogate may still leave valid operator convergence. The audit should preserve what survived and remove what did not.

## 12. Final boundary

Scale-bridge evidence is useful.

Scale-bridge evidence is not continuum proof.

The correct posture is not pessimism. It is recoverable coherence under stronger interaction with controls, refinement, and compression.
