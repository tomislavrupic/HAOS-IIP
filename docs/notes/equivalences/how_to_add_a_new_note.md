# How to Add a New Equivalence Note

Use this checklist when adding a new note to the equivalences folder.

## Before writing

1. Pick a comparison class that already appears in frozen HAOS-IIP language.
2. Decide whether the strongest supported reading is equivalence, analogy, or rediscovery.
3. Set the claim ceiling first.

## The note must include

1. A status line with scope and claim ceiling.
2. A candidate equivalence statement.
3. A short justification grounded in existing repo language.
4. Shared features and non-shared features.
5. Evidence gates or failure conditions.
6. An audit summary that separates fact, design choice, heuristic, analogy, and unverified hypothesis.
7. Links to the most relevant frozen sources.

## Hard rules

- Stay inside frozen discrete/operator regimes.
- Do not promote structural correspondence into physical ontology.
- Do not use the note to reopen a frozen physics bridge.
- If the comparison is only heuristic, say that plainly.

## Folder hygiene

- Update `equivalences_index.md` when a new note is added.
- Update `equivalences_layer_overview.md` if the new note changes the summary.
- Keep the README and comparison-matrix links consistent.

## Good default

Write the note as if it will be read by a skeptical technical reviewer who is looking for the boundary, not the flourish.
